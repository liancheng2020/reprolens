# 评测集与双版本演示

## 目标与边界

本次增量回答两个问题：执行器能否正确区分 Bug、正常行为和执行受阻；从已确认计划生成的回归测试，能否在缺陷版失败、修复版通过。

这是固定计划的确定性执行器评测，不是 DeepSeek 规划能力评测。无需 API Key，不访问第三方页面，不统计虚假的 token 或费用。页面使用原生表单模拟失焦回滚行为，不声称覆盖了所有 React 受控组件问题。

不包含动态重规划、自动改代码、真实模型批量评测、公开多用户任务服务。本次只要求冒烟验证；完整 20 条数据集可按需运行。

## 设计

```text
评测实验室 / CLI
  -> 选择固定用例（数据集 v1）
  -> 启动随机端口的本机演示服务器
  -> 每条用例创建全新 BrowserContext
  -> Zod 校验计划 -> 复用 executePlan -> 截图与步骤证据
  -> 实际判定 + 步骤状态与标注比较
  -> 生成一份 regression.spec.ts
  -> 仅切换目标 URL，分别在缺陷版 / 修复版执行
  -> 检查 Playwright JSON 报告 -> 汇总 report.json
```

业务逻辑复用 `apps/api/src/business.ts`，未为评测另写一套模拟执行器。双版本复用同一份计划、定位和期望值；生成代码的 SHA-256 写入 manifest，避免通过修改断言“修好”测试。

## 用例集

定义位置：`apps/api/src/evaluation/cases.ts`。每条包含稳定 ID、场景、版本、期望判定、期望步骤状态、smoke 标记和完整计划。新增场景时同步扩展 `fixtures.ts`，不能仅添加预设结果。

| 场景（每项两版，共 20 条） | 缺陷 / 受阻版预期 | 修复版预期 |
| --- | --- | --- |
| 输入失焦丢值 | 已复现 | 未复现 |
| 输入框意外禁用 | 已复现 | 未复现 |
| 输入框意外只读 | 已复现 | 未复现 |
| 成功提示未出现 | 已复现 | 未复现 |
| 业务文案错误 | 已复现 | 未复现 |
| 加载遮罩未消失 | 已复现 | 未复现 |
| 延迟成功提示（正常版 600ms 后出现） | 已复现 | 未复现 |
| 同名输入框歧义 | 证据不足 | 未复现 |
| 未授权删除动作 / 改为无副作用按钮 | 证据不足，且未点击 | 未复现 |
| 前置页面标识缺失 | 证据不足 | 未复现 |

冒烟集为 `blur-bug`、`blur-fixed`、`ambiguous-bug`、`danger-bug`。危险操作用例额外检查动作标记，不能只靠“证据不足”的文字判定安全。

## 运行

在仓库根目录安装依赖和浏览器后执行：

```sh
npm run browser:install
npm run check
npm run eval:smoke
# 可选，非默认：
npm run eval:full
```

CLI 自带隔离演示服务器，不要求启动工作台。返回码 0 表示所有用例与双版本重跑符合预期；任何不符合、浏览器缺失、进程异常均返回非零。不是看到缺陷版测试失败就把整次命令判为失败。

可视化入口：正常启动工作台后，展开左侧“开发者工具”，点击“评测实验室”。默认 4 条；下拉可选 20 条。打开缺陷版 / 修复版可手动输入并按 Tab 对比；运行评测后展开用例，查看期望、实际、步骤状态和前后截图。普通用户可直接在工作台载入 UI / 交互示例，不必进入实验室。

API：`GET /api/evaluations/cases`、`POST /api/evaluations`（`{"suite":"smoke"}`）、`GET /api/evaluations/latest`。同一 API 进程只允许一个评测运行，重复启动返回 409；非法 suite 返回 422。运行中前端轮询最新状态，切换页面后再回来可继续查看。

当前最新任务索引保存在内存，重启后界面不恢复旧任务；CLI 与 API 的最新任务索引不共享。完整产物仍保存在磁盘，不覆盖已有任务。

如果浏览器下载受限，且本机已安装 Google Chrome，可在启动 API 或 CLI 的进程环境中设置 `REPROLENS_EVAL_CHANNEL=chrome`；评测使用独立无头上下文，不读取个人浏览器资料。默认仍使用 Playwright Chromium，两次重跑使用相同浏览器配置，实际浏览器版本记录在 manifest。不同浏览器版本的成绩不应直接比较。

## 产物与判分

每次产物位于 `artifacts/eval-<uuid>/`（已由 artifacts 忽略规则排除提交）：

- `report.json`：用例结果、真实耗时、指标、双版本重跑结论。
- `manifest.json`：数据集版本、同一计划、生成代码哈希和运行环境。
- `regression.spec.ts`、`playwright.config.ts`：实际执行的生成测试。
- `replay-bug.json`、`replay-fixed.json`：Playwright 原始结果。
- `<case-id>/*.png`：每条用例的步骤前后截图。

缺陷版重跑必须在生成代码的失焦后断言行失败，且期望值为 `repro-test`、实际值为空；输入前的断言失败、导航失败、浏览器启动失败、无测试结果、进程超时都不算成功检出。修复版必须测试通过且进程正常退出。

指标分母：用例符合率 = 判定、步骤状态与额外安全检查均符合的条数 / 已执行条数；判定准确率 = 实际判定与标注相等的条数 / 已执行条数（包括运行错误）；误报率 = 正常用例被判已复现 / 正常用例数；证据不足率 = 实际证据不足 / 已执行条数。分母为零返回 null，不显示为 0% 或 100%。平均耗时只包含用例执行，不含生成测试重跑。

正常的安全拦截可以计为符合预期，但不能计为“成功复现”。整个任务还必须完成全部选定用例与两次重跑，才标记通过。固定计划不会调用模型，因此模型调用为 0，token 和费用为 null。

生成测试默认 URL 属于已关闭的隔离服务器。如需手动复跑，启动工作台 API 后，设置 `REPROLENS_TARGET_URL` 为当前 `/demo/eval/blur?fixed=0` 或 `?fixed=1` 地址，并使用产物中的 Playwright 配置运行；不要修改测试断言。

界面验证可复跑：先 `npm run build` 并启动 API，再执行 `node scripts/verify-evaluation.mjs`。默认访问 `http://127.0.0.1:8787`，可用 `REPROLENS_TEST_URL` 指定其他本机端口。它会实际创建一次冒烟任务并截图到 `artifacts/evaluation-ui/`；服务端与验证脚本需使用相同浏览器配置。

## 必要验证与后续

单元测试覆盖数据集完整性、计划 Schema、双版本计划一致性、指标分母、零样本和回归报告判分；浏览器冒烟验证真实输入、失焦、歧义停止和危险动作拦截；生成测试在双版本实际重跑。

大规模真实模型评测后续独立设计：先冻结标注和数据集，加入真实 Bug 样本、模型 / Prompt 版本、重复次数和真实 token 用量，保留基线结果。不能把本次确定性回归的成绩写成模型准确率。
