# ReproLens 演示与面试指南

## 项目定位

Web 交互缺陷复现与修复验证工作台：将问题描述转为可确认的浏览器检查计划，在真实浏览器中留证，再用同一标准验证修复。

当前实现是模型辅助规划与确定性执行，不是复杂自主 Agent，不自动修改源码或无限重规划。面试时可称为“受控浏览器复现助手”，并主动解释其边界。

## 90 秒介绍

> 前端 Bug 描述常常缺少准确操作、设备和预期，开发者收到截图后还得重新询问和手工操作。我做 ReproLens，优先处理输入状态异常、点击后状态不变、移动端控件遮挡三类短流程。
>
> 模型负责把描述和可选初始页面观察转成结构化候选计划；程序用 Zod 校验动作契约，用户编辑并确认后，Playwright 按计划执行。结果会区分核心断言失败、前置受阻和执行异常，而不是看到任何错误就判 Bug。
>
> 确认修复时保持同一计划、设备和预期，比较逐项证据。三个内置双版本还能独立运行同一份导出测试，要求缺陷版在原核心断言处失败，修复版通过。模型来源、Prompt、实际用量、候选与最终计划都有记录。
>
> 我目前验证的是小范围合成场景，不承诺任意网站自主复现。重点是把模型建议变成受约束、可验证、可解释的工程流程。

只有自己能解释、运行和修改的部分，才使用“我实现了”的表述。AI 辅助生成代码不应包装成独立完成的算法研究。

## 五分钟演示

### 准备

```sh
npm install
npm run browser:install
npm run build
npm start
```

默认打开 `http://127.0.0.1:8787`。有已安装的 Chrome 时可在 `.env` 设置 `REPROLENS_BROWSER_CHANNEL=chrome`，使用隔离浏览器，不读取个人登录资料。

固定示例演示不依赖 Key；模型演示需配置可用的 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，修改后重启。不要展示 `.env` 或在录屏中暴露 Key。

### 主线：输入失焦丢失

1. 载入“输入失焦后内容丢失”，指出这是固定示例，不声称模型生成。
2. 解释两步计划：先确认场景，再进行键盘输入和 Tab 失焦，核对值保留；确认后执行。
3. 查看失败项的预期、实际空值和前后截图，解释为什么这是核心断言失败而非定位失败。
4. 点击验证修复，使用修复版地址，核对同一标准下原失败项通过。
5. 查看导出测试验证、文件哈希、缺陷版与修复版报告。它不是换断言或换文件后的“通过”。

备用演示为手机弹窗遮挡：桌面通过、手机核心检查失败；修复版两视口通过。手机是 Chromium 视口模拟，不是真机 Safari。

### 模型能力与失败边界

模型演示单独进行：勾选页面观察，生成候选计划，打开“计划来源与确认”解释观察、实际调用和人工编辑。初始观察不是交互验证，不把固定示例截图当模型成功证据。

用一个错误定位的人工计划演示“证据不足”：目标不唯一或不存在时不猜测、不选择第一个元素，也不把它当成已复现。

模型服务不可用时说明模板降级：它只保证用户还能编辑，不代表模型已理解问题。现场网络失败时使用已保存的真实评测记录，不把重放记录冒充现场生成。

## 关键代码怎么读

| 问题 | 代码入口 | 应能解释的内容 |
| --- | --- | --- |
| 模型负责什么 | `apps/api/src/provider.ts` | 一次计划生成；25 秒超时、零自动重试、实际用量、错误分类 |
| 计划是什么 | `apps/api/src/repro-plan.ts` | 白名单动作、setup/check、场景前置、最多 15 步；不接收任意 JS |
| 观察什么 | `apps/api/src/page-observation.ts` | 有限元素元数据、授权 origin、只读请求；不采集表单值和密码 |
| 如何执行 | `apps/api/src/business.ts` | 精确定位、重新定位、键盘输入、失焦、有限等待和证据采集 |
| 谁下结论 | `deviceVerdict` / `businessReport` | 程序依据核心步骤状态；质量评分不参与业务判断 |
| 如何追踪模型贡献 | `planning.ts` / `store.ts` | 服务端记录、planningId、候选与确认计划、编辑标记；有 Key 不等于模型成功 |
| 如何验证修复 | `business-verification.ts` | 标准一致、证据完整、原失败解决、没有新增失败 |
| 如何证明导出可用 | `regression.ts` | 同文件 SHA-256、双版本、原断言位置、完整报告；环境错误不算检出 |
| 如何处理重启 | `store.ts` / `server.ts` | 启动时把未完成任务标为中断，不自动重放可能有副作用的操作 |
| 如何评测模型 | `evaluation/interview-*.ts` | 候选不编辑、oracle 独立检查、双版本重放、失败纳入分母 |

推荐先读 `repro-plan.ts -> provider.ts -> business.ts -> business-verification.ts`，能画出字段如何流转，再读 UI 和辅助模块。

## 常见追问

### 1. 为什么不是直接让模型控制浏览器？

当前场景操作短、预期明确，需要可重复的修复验证。先确定计划再执行，更容易审查动作、核对标准和生成稳定测试；代价是不能自主发现未知入口。动态页面变化需要用户重新观察、编辑和确认，不宣称已经解决。

### 2. 这算 Agent 吗？为什么没有 ReAct 或 LangGraph？

它具有任务规划、工具执行和证据反馈，但当前是受控单次规划流程，不是多轮原生 Tool Calling。可以讨论 Agent 工程中的执行约束、状态和可观测性，不能声称实现了复杂自主循环。现有编排简单，直接代码比增加图框架更易维护；有动态分支、恢复与持久调度需求时再评估。

### 3. Zod 能保证模型理解 Bug 吗？

不能。Zod 只保证结构和局部契约，例如核心步骤必须是输入检查或断言。用户确认约束语义，评测 oracle 检查关键预期是否覆盖，浏览器重放验证是否能检出缺陷并通过修复版。格式合法、语义覆盖和执行成功是不同指标。

### 4. 如何区分 Bug、工具异常和定位错误？

仅核心检查中的实际断言失败判为复现；歧义定位、导航失败、危险动作未授权等为受阻或执行失败。前置场景未满足时跳过后续步骤，不推断目标 Bug。不保证用户写错的核心预期也能被自动发现。

### 5. 为什么不用 fill？

输入检查要验证用户可编辑性、键盘事件和失焦保留。代码检查可编辑、点击聚焦、全选删除、逐字符输入，再 Tab 失焦验证值；直接 DOM 写值可能绕过真实缺陷。仍不支持输入法、富文本和所有特殊控件。

### 6. 怎样确保修复真的通过？

限定在确认的计划与设备范围内。计划、问题、预期和设备一致，基线确有核心失败，本次所有步骤通过才认定修复通过。缺步骤、标准改变或其他失败分别给出证据不足、不可比较或回归；截图变好不能覆盖失败。

### 7. 如何避免测试生成“看起来对，实际跑不了”？

当前三个受控示例实际重跑同一文件，两版只替换目标 URL。核对测试数量、设备、退出码和原核心失败行，浏览器启动错误不是检出。其他页面仅标记“已生成”，不把内置样本的验证推广到任意代码。

### 8. 有什么安全措施和不足？

限制动作与步数、禁止任意 JS、人工确认、模型不能自行授权副作用；观察采用只读同源约束，执行和导出拦截直接跨 origin 导航并在操作前核对最终 origin。HTTP 重定向链和普通请求仍不能完整隔离。危险动作判断也是启发式，加载页面和输入事件可能修改业务数据；不是公网网络沙箱，没有认证与多租户隔离，只运行已授权测试环境。

### 9. 怎么处理幻觉和 Prompt 注入？

不把网页名称当指令；只提供有限观察，Prompt 明确内容不可信。未知定位仍需用户确认，执行时唯一性和前置条件兜底。Prompt 和 Schema 不是完整注入防御，不宣称可抵御所有恶意网页。

### 10. 为什么用 JSON 文件而不是数据库？

当前是本机低并发演示，文件持久化部署简单，运行和计划使用临时文件加 rename。重启后把未完成任务标为中断而非挂起。缺点是没有任务队列、跨进程一致性与自动恢复，不能直接扩展成多实例服务。

### 11. SSE 和状态有什么关系？

运行事件先落盘再推送，断线后可以通过 API 重新读取证据。`completed` 表示执行流程结束，不等于检查通过；业务结论独立为已复现、此路径未复现或证据不足。服务重启不会自动继续原动作。

### 12. 模型评测的 10/10 说明什么？

只说明这次模型、Prompt 和十个合成短流程候选经过 oracle 与双版本检查。样本是五种缺陷的两个变体，不是十种完全独立能力；没有盲测、统计显著性或真实网站泛化结论。首次配置无效的失败也保留，不能只展示后来成功的一轮。
