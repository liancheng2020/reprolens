# 页面观察与模型对照

## 目的

在保持 Bug 复现主线和人工确认不变的前提下，验证初始页面结构是否能改善模型生成的定位和检查计划。不实现多轮重规划，也不自动改变业务预期。

## 使用页面观察

工作台生成计划前，可勾选“允许访问已授权站点，并将初始页面元素名称发送给模型”。默认不勾选，不会因为填写 URL 自动访问网站。选中后先观察首个所选设备，成功后才调用模型；失败返回错误，不偷偷改成无观察规划。

在服务端 `.env` 配置完整 origin，多个以逗号分隔，然后重启服务：

```dotenv
REPROLENS_BROWSER_CHANNEL=chrome
REPROLENS_OBSERVATION_ORIGINS=http://127.0.0.1:8787,https://your-authorized-test.example
```

未配置白名单时，只允许当前 API 的 localhost / 127.0.0.1 origin。端口也属于 origin；使用 8793 等端口时，应同步调整显式白名单。只添加自己有权测试的站点，不添加生产敏感服务。

`POST /api/plans` 增加可选字段 `observePage: true`，返回的计划格式不变。观察摘要和限制通过计划 warnings 展示，执行前仍需人工确认。固定演示按钮载入预置计划，不调用模型，不属于模型对照。

## 观察边界

- 独立无头浏览器上下文，无个人 Cookie 或登录态；不点击、不填写、不主动滚动。
- 最多扫描 500 个候选节点，输出 50 个可见元素；名称最多 100 字符，超限标记截断。
- 仅收集标题、控件名称、候选定位、禁用/只读状态，不收集输入值、密码框、整页 HTML、脚本源码、截图或网络响应体。
- 对常见邮箱、长数字与密钥形式做尽力脱敏，但元素名称仍可能包含个人信息。用户授权不等于数据已完全去敏，不能提交敏感页面。
- 只放行同 origin 的 GET/HEAD，拦截 POST、跨域、WebSocket、Service Worker 和 HTTP 重定向。导航本身仍可能产生服务端副作用；不保证只读。
- 启动最多 10 秒，页面观察阶段最多 12 秒；模型调用另有 25 秒超时，无自动重试。
- 300ms 的初始观察窗口不保证 SPA 已就绪。第三方资源被阻止、未打开的弹窗、iframe、Shadow DOM、动态路由或登录页面可能缺少目标，需要用户检查。
- 这不是完整网络沙箱，不解决 DNS 重绑定、浏览器漏洞、全部私网访问和多租户隔离。继续仅面向本地授权测试，不应直接公开为任意 URL 浏览器服务。

## 模型输入与错误

两组使用同一模型、temperature=0、同一版本 Prompt 和输出 Schema，仅观察组多一个 observation 字段。Prompt 明确页面文字属于不可信数据，不得覆盖用户预期；即使看到 disabled / readonly，也不能将“应可输入”改成“应禁用”。这些提示不是对 Prompt Injection 的完整防护。

模型步骤必须经过既有 Zod 校验，副作用授权统一重置为 false。失败区分未配置、JSON 非法、计划非法、超时及请求失败，返回明确标记的待编辑模板。模板不算模型成功。

详细调用结果包含模型、Prompt 版本、耗时、实际 token 用量及校验错误。仅合成对照脚本主动保存原始模型输出；普通规划不保存原文到磁盘。未返回的用量记为 null，不把它当零成本。

## 小规模对照

```bash
npm run eval:model
# 可选：每组每场景重复 3 次，总共 18 次模型调用
npm run eval:model -- 3
```

需已有 DeepSeek Key 及可用浏览器；本机使用系统 Chrome 时在命令前加 `REPROLENS_BROWSER_CHANNEL=chrome`。默认 3 个合成输入场景、两组各一次，共 6 次调用。场景为失焦清空、意外禁用、意外只读。没有真实个人资料，不向模型发送缺陷开关、源码或人工答案。

每个场景交替 baseline / observed 的执行顺序，缓解顺序偏差但不保证可重复确定性。模型仅在第一版页面上规划一次，同一份计划原样应用于缺陷版和修复版；报告保存计划哈希。

双版本正确要求：

1. 模型成功返回合法计划，不能来自模板降级。
2. 核心检查必须实际验证目标输入框的输入能力；仅检查可见、选错目标等不能算成功。
3. 缺陷版核心检查失败且判定已复现；修复版所有步骤通过且判定未复现。
4. 执行错误、定位歧义、非预期操作和未完成均进入分母，不能当检出成功。

对照只允许最多 6 步 input / assert；其他动作计为样本失败，不执行。此限制适用于这组输入任务，不代表主产品只支持输入。

产物位于 `artifacts/model-compare-<id>/`：`report.json` 保存数据集版本、原始模型输出、观察、计划、实际 token、步骤与失败；`summary.md` 汇总成对正确数与端到端平均耗时。这里重放主执行器，不替代既有导出测试的完整 Playwright runner 验证。

3 个同类合成场景不能证明真实网站成功率、UI 场景覆盖或统计显著性。训练式迭代用过的场景不是留出集；后续应增加未调参的场景和重复运行。若观察组没有改善，应保留结果并分析失败，不修改判分凑成绩。

## 本地验证

```bash
npm run check
REPROLENS_BROWSER_CHANNEL=chrome node scripts/verify-observation.mjs
# 检查正在运行的工作台桌面/手机布局
REPROLENS_BROWSER_CHANNEL=chrome REPROLENS_TEST_URL=http://127.0.0.1:8793 node scripts/verify-observation.mjs
```

浏览器脚本检查候选提取、输入值和密码排除、POST/跨域/重定向阻止，以及可选的界面同意框和无横向溢出。

## 本轮实际结果

首次使用 `observe-plan-1`：baseline 0/3、observed 0/3。主要失败为模型遗漏必填授权字段及不符合步骤契约，均按失败保留。定位后只澄清 Prompt 的必填字段、setup/check 约束和 input 已含失焦验证的语义，没有放宽 Schema 或判分。

第二轮两组统一使用 `observe-plan-2`：

| 模式 | 双版本正确 | 平均端到端耗时 |
| --- | --- | --- |
| 无页面观察 | 0/3 | 6.35 秒 |
| 有页面观察 | 3/3 | 13.12 秒 |

这些样本已用于本轮开发调试，不是留出集。3/3 只说明本轮有限样本符合预期；没有统计显著性结论，不能写成“模型准确率 100%”。耗时包括观察、模型和双版本执行；失败组可能提前结束，不能当成模型响应速度的公平对比。
