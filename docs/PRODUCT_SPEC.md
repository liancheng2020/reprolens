# ReproLens 产品设计

## 产品目标

把一条模糊的 Web Bug 描述转化成开发者可以验证、共享和继续处理的工程资产：浏览器操作轨迹、跨设备截图、运行时证据、结构化结论和 Playwright 回归测试。

## 项目边界与迭代原则

ReproLens 的前端工作台、API、浏览器执行器、持久化、测试和内置 Demo 均在当前仓库中交付，可以独立安装、启动和演示。

项目按用户需求小步迭代。每个版本先定义用户闭环和验收标准，再完成设计、实现、自动化验证与文档更新；尚未形成明确需求的能力只进入候选列表，不提前增加主流程复杂度。

## 目标用户

- 前端开发者：缩短复现和补回归测试的时间。
- QA 工程师：自动采集标准化证据，减少重复操作。
- 开源维护者：快速判断 Issue 是否可复现。
- 独立开发者：在没有专职 QA 的情况下完成基础验证。

## v0.1.0 — 核心复现闭环

### 用户路径

1. 用户打开工作台。
2. 输入 URL、问题描述和期望结果。
3. 选择 Desktop、iPhone 13 或 Pixel 7。
4. 点击启动可视化复现。
5. 页面进入运行详情，实时展示 Agent 时间线。
6. 每个设备完成后出现截图与结构化发现。
7. 任务完成后展示结论、置信度、评分和回归测试。
8. 用户复制测试代码，或从历史记录重新打开结果。

### 界面范围

#### 工作台

- 项目价值主视觉
- 累计运行、复现次数、平均评分、Provider 状态
- 任务输入表单
- 多设备选择器
- 最近运行列表

#### 运行详情

- 复现结论、置信度、耗时、引擎、质量评分
- 模拟浏览器证据区和设备切换
- 实时 Agent 执行时间线
- 按严重程度展示的结构化发现
- 可复制的 Playwright 测试代码
- Console、Network、A11y 和设备统计

### 验收标准

- 新用户安装后 5 分钟内可以运行内置 Demo。
- 用户不需要阅读日志就能判断问题是否复现。
- 每个高优先级结论都有浏览器或运行时证据。
- 没有 DeepSeek Key 时，基础检测仍能运行。
- 生成测试不包含模型凭空发明的选择器。
- Windows 和 macOS/Linux 都有明确启动说明。

## v0.2.0 — 修复验证闭环

该版本在核心复现能力上增加“验证修复是否有效”的完整闭环。

### 用户路径

1. 用户打开一条已完成的复现任务，并将其作为不可变基线。
2. 输入修复后页面地址，系统复用原问题、期望结果、设备矩阵和 Agent 操作路径。
3. 每个设备完成重新扫描后，系统对不同尺寸的全页截图做白色画布归一化。
4. 本地像素引擎生成 Before、After、Pixel Diff，并计算变化比例。
5. 确定性规则对比质量分和去重后的问题根因，输出修复有效、发现回归、视觉变化或基本无变化。

### 界面增量

- 已完成任务提供修复后 URL 输入和“验证修复”入口。
- 验证结果展示质量分变化、已解决问题、新引入问题和像素变化率。
- 同设备展示 Before、After、Pixel Diff 三联证据，并与设备切换保持同步。

### 验收标准

- 不依赖 AI Provider 也可以完成像素对比与修复结论。
- 同一验证任务同时保留运行时证据、结构化发现和视觉 Diff。
- 基线缺失、未完成或缺少目标设备截图时，API 返回明确的 4xx 错误。
- 内置 Demo 可以在本机完整演示故障版到修复版的闭环。
- 前端在桌面和移动尺寸下均可查看三联证据。

## v0.3.0 — GitHub 协作闭环

当前版本把 ReproLens 从本地验证工具延伸到开源仓库和研发协作流程，但 GitHub 适配层不直接依赖 Browser Scanner、Analyzer 或 Visual Diff 的内部实现。

### 用户路径

1. 维护者按 Issue 模板收集 Target URL、问题、期望结果和测试设备。
2. 添加 `needs-reproduction` 标签，或在工作台粘贴 Issue URL。
3. GitHub Actions 或本地服务读取 Issue 和仓库配置，并基于 Issue 与当前提交创建幂等任务。
4. 任务执行期间创建进行中的 Check Run；UI 同步展示仓库、Issue、提交和发布状态。
5. 扫描完成后将结论、评分、发现和证据清单写入 GitHub Check 与 Issue 评论。
6. 截图、Pixel Diff、Run JSON、Markdown 报告和 Playwright 测试作为 Actions Artifact 下载。
7. 维护者可安全重试；ReproLens 更新原评论和 Check，不制造重复消息。

### 界面增量

- 首页增加 GitHub Issue 导入面板，明确展示 Token 配置状态与工作流能力。
- 运行详情增加 GitHub Context 卡片，展示仓库、Issue、提交 SHA、同步结果与外链。
- 已完成任务支持手动发布或重新发布，用于权限恢复和失败重试。

### 验收标准

- Fork 仓库后，只需开启 Actions 权限即可对公开页面执行确定性验证。
- 同一个 Issue、同一个提交在重复事件下只对应一个运行任务。
- 标签触发、手动 workflow_dispatch 和 Web UI 导入共用同一解析与执行逻辑。
- Issue 评论通过隐藏标记 upsert，不因重试重复刷屏。
- Check Run 与 ReproLens 最终状态保持一致，报告包含可定位的证据摘要。
- GitHub Token 与 Webhook Secret 只从环境变量读取，API 配置响应和日志不包含凭据。
- Webhook 使用原始请求体和 HMAC-SHA256 校验，无效签名返回 403。
- 不配置 DeepSeek Key 时 GitHub 工作流仍能完成扫描和报告。
- GitHub 集成测试可独立运行，不修改扫描器、分析器和 Diff 引擎。

## v0.4.0 — 页面质量分析闭环

### 用户路径

1. 用户按原有方式创建复现任务，无需额外配置即可启用默认质量门禁。
2. Browser Scanner 在每个设备中运行 axe-core WCAG 2 A/AA 审计并采集 Web Vitals。
3. 确定性分析器将审计结果转为带规则编号、DOM 定位、元素坐标和修复建议的 Finding。
4. 系统按最低评分、高严重度、可访问性和性能问题上限计算质量门禁。
5. 运行详情展示设备级指标与门禁原因；运行记录按页面、设备和问题类型展示趋势。
6. GitHub 任务在门禁失败时阻断 Check，并把原因同步到 Issue 报告。

### 界面增量

- 运行详情增加页面质量报告，支持随设备标签切换 Web Vitals。
- 结构化发现增加 DOM 选择器、元素坐标、修复建议和 axe 规则链接。
- 运行记录增加页面筛选、最近评分趋势、问题类型累计和设备平均分。
- 质量指标采用 good、needs improvement、poor 三档视觉状态。

### 默认质量门禁

- 最低质量评分：75。
- 高严重度问题：0 个。
- 可访问性问题：不超过 3 个。
- 性能问题：不超过 2 个。

仓库可通过 `.github/reprolens.yml` 覆盖阈值或关闭门禁。性能阈值遵循 Core Web Vitals 常用分档，评分与阻断均由本地确定性规则完成。

### 验收标准

- axe-core 不可用或单条规则解析失败时，不影响基础截图和运行时证据采集。
- 每个可访问性 Finding 至少包含规则编号、选择器和可执行修复建议。
- 每个设备独立保存性能指标与设备质量评分。
- 旧版 JSON 运行记录在 v0.4 前端中仍可打开。
- GitHub Check 的质量阻断原因与运行详情一致。
- 趋势接口最多返回最近 30 条已完成任务，并支持按 URL 过滤。

## 后续迭代候选

- 自动修改被测项目业务代码
- 未经确认自动创建 GitHub PR
- 登录态托管和团队权限
- 公网多租户执行
- Figma 设计稿同步
- 桌面应用自动化

这些能力会扩大安全边界和交付周期，只有在形成明确用户需求和验收标准后，才会进入对应版本规划。
