# ReproLens 版本说明

本文档用于快速了解 ReproLens 每个版本解决的问题、核心能力和用户能够看到的结果。

## 版本总览

| 版本 | 主题 | 解决的问题 | 直观产物 | 状态 |
|---|---|---|---|---|
| v0.1.0 | Bug 自动复现 | Bug 描述模糊、人工复现耗时 | 浏览器截图、执行时间线、问题报告、Playwright 测试 | 已完成 |
| v0.2.0 | 修复效果验证 | 修改代码后无法快速确认问题是否真正修复 | Before / After / Diff、质量分变化、修复结论 | 已完成 |
| v0.3.0 | GitHub 协作闭环 | 验证结果停留在本地，无法融入研发协作 | Issue 自动任务、GitHub Check、Issue 报告、Actions Artifact | 已完成 |
| v0.4.0 | 页面质量分析 | 扩展质量维度 | WCAG、Web Vitals、门禁和趋势 | 已完成 |
| v0.5.0 | 业务断言驱动的复现 | 复现结果偏离用户问题 | 确认计划、业务检查、步骤证据和测试 | 当前版本，待完整验收 |

## 演进路线

```text

```

## v0.1.0：从 Bug 描述到复现证据

### 版本目标

让用户只需要提供目标页面、问题描述和期望结果，就能获得一次可以查看、保存和复用的自动化复现结果。

### 核心能力

- 使用真实 Chromium 打开并操作目标页面。
- 支持 Desktop、iPhone 13、Pixel 7 三种设备尺寸。
- DeepSeek 根据 Issue 和页面可交互元素规划受限操作。
- 模型只能使用 click、fill、wait 白名单动作，不能执行任意脚本。
- 通过 SSE 实时展示 Agent 执行时间线。
- 采集页面截图、Console Error、Page Error 和 HTTP 错误。
- 检测横向溢出、图片替代文本、无名称控件和内容裁切。
- 输出复现结论、置信度、质量评分、结构化发现和 Playwright 测试。
- 没有 DeepSeek API Key 时自动使用本地确定性规则。

### 用户看到的结果

一次任务结束后，运行详情会展示：

1. 问题是否成功复现。
2. Agent 执行过哪些操作。
3. 不同设备下的页面截图。
4. 每个问题对应的浏览器证据。
5. 可以复制执行的 Playwright 回归测试。

## v0.2.0：从复现结果到修复验证

### 版本目标

让用户在修改代码后，用同一套问题描述、操作路径和设备重新验证，并直观看出修复前后的差异。

### 核心能力

- 将任意已完成任务设为不可变基线。
- 对修复后的 URL 重放相同验证流程。
- 按设备生成 Before、After 和 Pixel Diff。
- 对不同高度的页面截图进行白色画布归一化。
- 统计像素变化率、质量分变化、已解决问题和新引入问题。
- 输出 improved、regressed、changed 或 unchanged 确定性结论。
- 内置 Demo 同时提供故障版与修复版，方便快速演示。

### 用户看到的结果

```text
修复前截图          修复后截图          像素差异图
   Before      →      After       →       Diff
                         │
                         ▼
          评分变化 + 已解决问题 + 新问题
                         │
                         ▼
              修复有效 / 发生回归
```

## v0.3.0：从本地验证到 GitHub 协作

### 版本目标

让开源维护者和研发团队直接从 GitHub Issue 发起验证，并在原有协作位置查看结果。

### 核心能力

- 在工作台粘贴 GitHub Issue URL 创建任务。
- 自动解析 Issue 中的 Target URL、Problem、Expected behavior 和 Device。
- 支持 `needs-reproduction` 标签触发 GitHub Actions。
- 支持在 Actions 页面输入 Issue 编号手动执行。
- 使用 repository、Issue number 和 commit SHA 识别重复任务。
- 创建 GitHub Check Run，并同步进行中和最终状态。
- 在 Issue 中发布结构化报告，重复发布时更新原评论。
- Actions Artifact 包含截图、Pixel Diff、Run JSON、Markdown 报告和 Playwright 测试。
- 运行详情展示仓库、Issue、commit、Check 状态和 GitHub 跳转链接。
- 可选 Webhook 模式支持 HMAC-SHA256 签名验证。

### 用户看到的结果

```text
GitHub Issue / needs-reproduction 标签
                  │
                  ▼
          GitHub Actions 启动
                  │
                  ▼
         ReproLens 浏览器验证
            ┌─────┴─────┐
            ▼           ▼
      GitHub Check   Issue 报告
            │           │
            └─────┬─────┘
                  ▼
       下载截图、Diff 和测试文件
```

## v0.4.0：页面质量分析

### 版本目标

在 Bug 复现之外，增加更完整的页面质量检查，让 ReproLens 可以用于提交前检查和持续质量回归。

### 核心能力

- 集成 axe-core，按 WCAG 2 A/AA 规则输出可访问性问题。
- 按设备采集 LCP、CLS、INP、FCP、TTFB、DOM Ready、资源数量和传输体积。
- 使用确定性阈值生成性能 Finding，不由模型判断指标好坏。
- 在运行详情展示设备评分、指标评级、DOM 选择器、元素坐标和修复建议。
- 在运行记录按页面筛选质量趋势，并汇总设备平均分与问题类型。
- 支持最低评分、高严重度、可访问性和性能问题数四种质量阈值。
- GitHub Check 在质量门禁失败时返回 failure，并在 Issue 报告中列出原因。
- 旧版运行数据继续可读，不要求迁移 JSON Store。

### 用户看到的结果

每次任务除复现结论外，还会交付一份页面质量报告：质量门禁状态、设备级 Web Vitals、WCAG 问题定位、修复建议和历史质量趋势。

## v0.5.0：业务断言驱动的 Bug 复现

状态：设计与实现完成，完整场景验收待执行。此版本不是隔离 Worker / 队列版本。

### 目标与产品流程

用户报告“注册输入框无法输入”，必须到达注册场景、操作该控件、检查输入值；不能用 CLS、无障碍或无关 404 代替复现证据。

工作台：填写 URL / 问题 / 期望 → 生成计划 → 编辑目标、步骤、检查项和测试数据 → 确认 → 运行 → 查看按设备的业务证据。更改原始问题会使计划失效。重新编辑历史任务保留原计划供修改。

### 数据设计

- ReproPlan：版本、目标、验收范围、警告、最多 15 个有序步骤。
- ReproStep：setup / check 两类用途；click、input、assert、reload 四种动作。
- ReproTarget：精确 label、placeholder、text、role 或高级 CSS 定位。
- StepEvidence：设备、步骤、期望、实际、状态、定位信息、前后截图。
- BusinessReport：按设备结论、核心覆盖数、步骤列表、测试生成状态。
- 所有字段经过 Zod 校验。核心检查前必须有场景可见性或 URL 前置断言。

### 执行与判断

执行器每一步重新解析 Locator，不复用其他设备的临时元素编号。目标匹配多项、找不到目标、前置断言失败、授权不足均停止该设备的后续步骤，返回 blocked，其余步骤为 skipped。

input 使用普通点击、聚焦、全选清空、逐键输入、值断言、Tab 失焦与再次值断言，不使用 force 或修改 DOM 绕过问题。只支持普通 input / textarea；密码、富文本和特殊日期控件不在本版范围。

- reproduced：已确认场景下，核心断言失败；不能由普通执行错误触发。
- not_reproduced：该设备所有核心检查均执行且通过，仅代表此确认路径。
- inconclusive：前置条件或执行受阻、缺少检查证据。
- 任一设备复现则汇总结论为已复现；报告保留各设备差异。
- 执行状态 completed / failed 与业务结论分离，不再使用固定置信度。
- 每步有限超时；每设备 90 秒调度预算，预算耗尽不启动新步骤。当前在途步骤仍受各自超时限制。

### 业务检查项

支持输入值、文本、可见/隐藏、可用/可编辑、URL，以及最近操作后同源、路径和方法匹配的响应。响应必须唯一匹配，否则证据不足；该关联是时间窗口关联，不宣称已经证明后端因果关系。

响应字段为可选点路径，禁止常见敏感字段。只接受声明 Content-Length 且不超过 64KB 的 JSON，无法读取时给出受阻而不是产品 Bug。不支持跨域接口匹配。

### 界面与回归交付

主报告展示目标结论、核心覆盖、逐步期望/实际及截图。页面质量发现和分数默认折叠，不能替代业务结论。

测试导出使用同一份确认计划、相同定位与检查类型生成 Playwright 代码，不由模型自由编写。生成不等于已验证；存在受阻或跳过步骤时标为草稿。必须后续用故障版失败、修复版通过来验收。

重新验证可重放计划；像素和质量变化只是附加结果，不能证明业务修复。旧记录标为旧版质量扫描，不迁移为业务验证记录。

### API 与 GitHub

- POST /api/plans：只生成候选计划，不访问页面；模型不可用时返回待用户编辑的模板。
- POST /api/runs：接受 plan 和 planConfirmed。
- POST /api/runs/:id/replan：编辑后创建新运行，可继承 Issue 来源。
- POST /api/runs/:id/verify：重放已确认计划。
- 没有确认计划的自动化/Issue 任务不再盲点按钮，而是返回证据不足。可进入工作台编辑计划并重新执行。
- GitHub 报告分开显示业务证据与质量门禁；证据不足为 neutral。完整核心检查通过后仍可因独立质量门禁失败而返回 failure。

### 安全与已知边界

仅面向本机和可信测试环境；计划确认不是通用授权系统。表单提交及常见删除、发送、支付动作需逐步授权；启发式检测不保证识别所有副作用，自定义业务按钮仍需用户审阅。输入操作也可能触发业务请求。

密码输入不支持，截图遮罩 password 控件；不自动采集请求头。截图和页面文本仍可能包含其他业务信息，请使用合成数据，不要将敏感页面报告公开发布。

模型只根据描述提出定位建议，不读取页面后动态生成计划。当前实现是“逐步重定位”，尚不包含页面元素候选选择器、自动分支重规划或自动修正定位。模糊目标需要用户编辑后重试。安全模板不代表系统已理解所有业务期望。

### 待验收场景

按用户要求暂缓大规模测试。后续优先验收：注册输入框只读、输入后清空、正常输入、注册入口受阻、重复目标、无关 404、购物车数量、保存后刷新丢失。每个场景都需核对运行报告与导出测试的一致性。

源码划分：repro-plan.ts（校验与提示）、provider.ts（计划生成）、business.ts（执行和结论）、business-test.ts（确定性导出）、scanner.ts（浏览器与附加审计）、Business.tsx（编辑与证据 UI）。

## 版本边界

ReproLens 按“一个版本解决一个完整用户问题”的方式迭代：

- v0.1 负责复现问题。
- v0.2 负责验证修复。
- v0.3 负责连接 GitHub 协作。
- v0.4 扩展质量检测维度。
- v0.5 以业务断言验证指定问题。

自动修改业务代码、未经确认创建 Pull Request、托管登录态和公网多租户执行不属于当前版本范围。
